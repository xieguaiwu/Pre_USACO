## 三、三个核心问题（按严重度排序）

### 问题 ① 弃坑模式：外部作业能完成，自主练习必断

对比非常清晰：

- **有外部驱动**（0717/0720/0726 课业）：当天做完、当天 commit，完成率高。
- **自主练习**：7 个半成品全部停在「读入数据」那一步——
  - `LifeguardsB.cpp`：6 行，只声明未写；
  - `ShellGame.cpp`：读完输入就停；
  - `RotateAndShift.cpp`：`int current_pos[INT_MAX]`，编译都过不了；
  - `LivestockLineup.cpp`：Java 的 `indexOf` 混进 C++（课件干扰）；
  - `market_day.cpp` / `teacher.cpp` / `地毯`：半成品。

**结论**：瓶颈不在智力，在练习的启动成本和完成闭环。竞赛编程的进步 90% 来自「把题做完」这个动作，而历史数据里这个动作只在外部压力下发生。

### 问题 ② 考场工程 = 0，最便宜的致命失分点

- **54 个 cpp，0 个 `freopen`**。USACO 所有题要求文件 IO（如 `ride.in`/`ride.out`），现场忘写 = 每题直接 0 分，与算法水平无关。
- **从未用过 usaco.org 判题机**（本地也不判样例，samples 是 8 月才出现的手工文件）。
- **零限时模拟、E 组近年真题（8 组）零接触**——而路线图明确写了「E 组考前 2-3 周限时模拟」。
- 反复出现的 bug 模式：off-by-one（地毯题 `j < x1` 漏最后一行）、VLA、栈数组未初始化、输出无分隔。解法 = 「写完立刻本地判样例」的肌肉记忆。

**好消息**：这块成本极低，一个模板 + 判题脚本半天永久解决（已于本会话落地，见第五节）。
