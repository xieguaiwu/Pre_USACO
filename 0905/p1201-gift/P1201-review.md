## 2. 🚨 逻辑错误（1 处，潜伏未爆发）

- **位置**：`P1201-solve.cpp:22`
- **问题**：`int avg = geben > 0 ? geben / givenum : 0;`——护栏检查**被除数** `geben`，除零风险在**除数** `givenum`。题面允许 钱∈[0,2000] × g∈[0,n] 任意组合，**(钱>0, 人数=0) 是合法输入**
- **为何 AC**：洛谷数据不含 (+,0) 组合（含则首交 RE）。正确性以题面为准，不以数据为准
- **⚠️ 最小修复只改 22 行**：条件 `geben > 0` → `givenum > 0`。**23 行不能跟着改**——若两处"保持一致"都改：(100,0) 时 meingeld=0、净变 −100，钱凭空消失，从「崩溃」退化成「静默错账」，更危险。只改 22 行则下游自洽：avg=0 → meingeld=100−0=100 → 净变 0 ✓
- **根因**：边界枚举没取笛卡尔积。(钱∈{0,+})×(人数∈{0,+}) 四格，样例只覆盖 (0,0)(0,+)(+,+)，恰好漏掉唯一致命的 (+,0)
- **错因标签**：边界特判漏
- **30 秒自检法**：每个除法/取模问三句——分母题面最小值是几？谁保证它非零？**护栏变量是不是分母本身**？

## 3. ⚠️ 边界/安全风险（2 处）

1. **`string` 的 VLA ×2**（9–10 行：`names[n]` / `Nnames[n]`）——GCC 扩展非标准 C++（`-pedantic-errors` 拒编）；cpt 参数 `-Wall -Wextra -Wshadow` 不含 `-Wvla`，编译期零提示。本次 n 先读后用、尺寸合法，但非平凡类型的 VLA 是栈上限赌博，n 放大先死的是它
2. **`Nnames` 数组整体多余**——接受者读入后立即 `total[Nnames[j]] += avg`，此后无人引用，单个复用 `string` 即可。删掉它同时消灭：一个 VLA + 一条隐式约束（数组尺寸 n、循环上界 givenum，安全性完全押在题面 g≤n 上而无检查）

## 4. ℹ️ 技术精进（4 条）

1. **代数收缩**：`meingeld − geben` ≡ `−(givenum × avg)`——送礼人净流出恒等于「实际送出总额」。`meingeld` 变量连同其三元护栏可整体删除，账目收缩成一行减法，**全程序只剩除法一处需要护栏**。本次 bug 正是「多余护栏判错变量」的代价——移动部件越少，越没地方护错
2. **容器选型方法论**：n≤10 时 map 的 O(log n) 无感，但此题本质是「名字→下标」坐标压缩——通用套路是读入时发 int 编号、账目用 `vector<int>` 消掉 log 因子。n→2×10⁵ 时这是标准动作（VLA 同刻退场）
3. **int 充分性要算不要默认**：|净额| ≤ n×2000 = 20000，富余 5 个数量级——但这是从约束**推出来**的。约束放大（Σ钱 > 2³¹）的那一刻就是换 `long long` 的那一刻
4. **仓库卫生**：`2` 是不编译的死草稿（底部对 int 取下标 `geben[i]`；其 avg 裸除无护栏）——证明护栏是后补的、且后补时没重推分母。不应留在仓库
