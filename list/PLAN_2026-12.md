### 1.4 ⚠️ 重要事实修正（推翻 09-05 报告的一处结论）

09-05 诊断写：「USACO 所有题要求文件 IO，忘写 freopen = 每题 0 分」——**这是错的**。usaco.org 官方规则页原文（2026-09-15 现查）：

> "Note that as of the **December 2020 contest**, input and output switched from file-based to terminal-based, using **standard input and standard output** (e.g., cin and cout in C++). The input and output spec of a problem will specify which mode is being used."

**正确结论**：
- **2020 年 12 月及以后的所有比赛题 = 标准输入输出**（`cin` / `cout`），**不要 freopen**。
- 只有 **2020 年 12 月之前的老题** 和 **USACO Training 页面**（如 `ride.in` / `gift1.in`）才是文件 IO。
- 所以真正要练的肌肉记忆不是「无脑加 freopen」，而是 **每道题先看 I/O 说明那一行**。加错的 freopen = 直接 0 分（比不加更危险）。

`template.cpp` 里的 freopen 双行保持注释状态即可；做 2020 前老题时才取消注释。

## 3. 总战略：第一场要的是 **Bronze 满分**

### 3.1 为什么必须是 1000 而不是 750

- 750 分 = 赛后等放榜升 Silver，**浪费掉当场那 4 小时**。
- 1000 分 = 当场升 Silver，**白赚一整场 Silver 实战**（摸底 + 为第二场铺路）。这是本赛季规则下唯一的「加速器」。
- 你的时间只够打好两场：**12 月 Bronze 满分 → 当场 Silver → 1 月末 Silver 700+ → 当场 Gold**。

### 3.2 1000 分怎么拿（考场时间分配，4 小时）

| 阶段 | 用时 | 动作 |
|---|---|---|
| 通读 3 题 | 15 min | 每题写下：输入规模 / 输出 / 约束 / 第一反应 |
| 排序 | 5 min | 按「把握度」排序，不是按题号 |
| 简单题 | 40–50 min | 写完 → 样例 → 边界（最小/最大/重复）→ 提交 |
| 中档题 | 60 min | 同上；**先交暴力拿分，再优化** |
| 难题 | 60–75 min | 暴力版先交（333 分里先锁住 100+），再想正解 |
| 缓冲 | 20–30 min | 回头检查输出格式（换行、空格）、特判 n=1 |

**铁律**：任何一题先保证有提交、有分数。零提交 = 0 分，最亏。

### 3.3 当场 Silver 怎么打

Bronze 满分后**先休息 20–30 分钟**（喝水、走动、闭眼），再点开 Silver（计时器重置为全新 4 小时）。Silver 目标不是满分，是**拿多少算多少 + 摸清差距**，回来后照实写战报。

## 4. 每日基本盘（三种日型）

> 你说过在校日有 1.5–2 小时自由时段。按下面两种日型执行；**具体几点做不重要，重要的是当天闭环完成**。

### 4.1 标准日（周一–周四，90 分钟）

| 时段 | 时长 | 动作 | 完成标志 |
|---|---|---|---|
| ① 读题 | 15 min | **不碰键盘**：读英文/中文题面，手推样例，白纸写伪代码 | 能一句话说出算法 |
| ② 写码 | 45–60 min | 单题，45 分钟硬上限 | 编译通过 |
| ③ 判题 | 10 min | `cpt` 判样例 + **自造 3 组**边界（最小 / 最大 / 特殊） | 全绿 |
| ④ 收尾 | 5 min | `git commit`，message 写「用时 / 卡点 / 错因」 | 提交完成 |

**加餐（有余力）**：第二题，或重做一道错题。

### 4.2 周五（3 小时）：知识日

- 60 min **学一个新工具**（前缀和 / 二分 / BFS / 并查集……）→ 手写 3 遍
- 60 min **用它做 1 道题**
- 30 min 把新知识写进 `IO_Error_Checklist.tex`

### 4.3 周六（3–4 小时）：题组日

- 2 道题**限时**（各 45 min，严格计时）
- 90 min 讲评 + 台账回填

### 4.4 周日（4–5 小时）：模拟日 🔥

- **4 小时全真模拟**（见 §7 指定场次）：模拟环境 = 空文件裸写、无模板、无 AI、无参考、计时器打开、只开题面
- **90 分钟讲评**：每题三问 —— ①我第一时间的想法 ②正解思路 ③我的错因（写进台账）
- 15 min 写周报（§11）

### 4.5 与 `Today` App 对齐（重启每日打卡）

| Today 步数 | 含义 |
|---|---|
| 第 1 步 | 读题 + 手推样例完成 |
| 第 2 步 | 代码写完（编译通过） |
| 第 3 步 | `cpt` 判过 + commit |
**满 3 步才算一天**——这正是你要练的「闭环」本身。

## 5. 熔断与追赶规则（防再次断档）

| 场景 | 规则 |
|---|---|
| 某天只剩 20 分钟 | 只做保底线：读题 + 手推样例 + 记一句话。**链条不断就算成功**。 |
| 卡题 45 分钟 | 允许看**思路**（不是代码）→ 合上，自己重写。仍卡 → 当天降级为暴力版，**必须 commit**。 |
| 连续 2 天没做 | 第 3 天只做**保底线**，禁止补偿式刷 5 题（会再次崩盘）。 |
| 一周落后 ≥3 题 | 砍掉当周「加餐」，核心题顺延到下周，**不跳题**。 |
| 想直接看题解代码 | 禁止。允许看思路与复杂度，禁止看实现。 |
| 某题实在做不出 | 登记到 `PROGRESS.md` 的「待攻」区，两周后二刷。 |
| **W1–W2 爬坡期** | 按 **60% 折算**：两天只完成一天也算达标。爬坡期不比总量，只比「链条有没有断」。 |
| **学校考试周 / 大作业周** | 整周降为保底线（每天 20 分钟读题）。**学校成绩优先**，本计划不与你抢时间。 |

## 8. 考场工程 checklist（11/30 前必须全部打勾）

### 8.1 赛前必须练出来的 6 个动作

- ☐ 每道题**先看 I/O 说明那一行**（2020-12 之后是标准 IO；老题才是文件 IO）
- ☐ 输出**每行结尾都有换行**（官方明确点名：这是「本地过、判题不过」的第一大原因）
- ☐ 提交前自测：最小规模（n=1）、最大规模、特殊情形（全相同 / 有 0 / 负数）
- ☐ 语言下拉框选对（C++17）
- ☐ 反馈颜色会读：X / T / ! / E / M 各代表什么
- ☐ **裸写**能力：不从模板起步也能 5 分钟内起手（比赛禁用预制模板）

## 附录 D · 一页速记（考前 3 天只看这页）

| 类别 | 口诀 |
|---|---|
| I/O | 先看 I/O 说明；**每行结尾换行**；不滥用 freopen |
| 边界 | n=1 / n=最大 / 全相同 / 有 0 或负数 / 首尾元素 |
| 溢出 | 和、积、前缀和 → `long long` |
| 数组 | 开 `n+5`；二维 `n+2`；禁用 VLA；禁用 `INT_MAX` 规模数组 |
| 排序 | 比较器必须严格弱序（`<` 不是 `<=`）；`priority_queue` 的 `greater` 是小根堆 |
| 二分 | 用 `l + (r-l)/2`；`l=mid` 时必须配 ceil 中点 |
| 前缀和 | `s[r]-s[l-1]`，`s[0]=0` |
| 差分 | 二维改 4 个角：`+ - - +`，终点是 `x2+1 / y2+1` |
| 复杂度 | n≥1e5 → O(n log n)；判题机 ≈1e8 次/秒 |
| 心态 | 先交暴力保分，再优化；每题必有提交 |
